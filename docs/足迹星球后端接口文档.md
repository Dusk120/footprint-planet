## 一、运行约定

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080/api` |
| 认证方式 | JWT，请求头携带 `Authorization: Bearer <token>` |
| 内容类型 | `application/json`（UTF-8） |
| 响应包装 | 统一 JSON 结构 `{ code, message, data }` |
| 成功标志 | `code = 0` |
| 分页响应 | `{ list: [...], total: 100, page: 1, pageSize: 10 }` |
| 时间格式 | 日期 `YYYY-MM-DD`；时间戳 `yyyy-MM-dd HH:mm:ss` |

### 1.1 统一响应包装

所有接口（成功）返回：

```json
{ "code": 0, "message": "ok", "data": { } }
```

`data` 的具体内容见各接口。失败时返回 **HTTP 4xx/5xx 状态码**，body 形如：

```json
{ "code": 400, "message": "用户名或密码错误", "data": null }
```

> 前端 `src/api/http.js` 会统一解包：非 2xx 或 `code !== 0` 均抛出 `message` 作为错误提示，因此各接口直接返回业务提示文案即可。

### 1.2 认证方式

- 标注「需要」的接口必须在请求头携带 `Authorization: Bearer <token>`。
- token 由登录 / 注册接口签发，前端存于 `localStorage`，键名 `footprint-planet:token`。
- 后端从 JWT 解析出当前用户身份，用于「我的数据」查询、作者校验、点赞用户标识等。
- token 失效 / 非法时返回 **401**，前端收到后清除 token 并跳转登录页。

### 1.3 命名映射约定

数据库使用下划线命名，接口（请求 / 响应）统一使用 **camelCase**，对应关系如下：

| 数据库字段 | 接口字段 | 说明 |
|---|---|---|
| `created_at` | `createdAt` | 时间戳 |
| `total_km` | `totalKm` | 累计里程 |
| `total_days` | `totalDays` | 累计天数 |
| `light_date` | `lightDate` | 点亮日期 |
| `start_date` | `startDate` | 出发日期 |
| `is_public` | `isPublic` | 是否公开 |
| `author_id` | `authorId` | note 响应中的作者 ID（跳转作者主页 / 判断「是否本人」） |
| `author_nickname` | `author` | note 响应中的作者昵称（仅展示） |
| `location_name` / `location_province` | `location.name` / `location.province` | note 地点（嵌套对象） |

其余字段名两端一致（如 `username`、`nickname`、`motto`、`avatar`）。

## 二、数据模型

> 说明：以下为物理表设计。接口返回的 JSON 字段名遵循上一节映射规则，**与表字段不完全同名**。

### 2.1 user（用户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 用户 ID |
| username | VARCHAR(50) UNIQUE | 登录名 |
| password | VARCHAR(100) | BCrypt 加密后的密码，**不出现在任何响应中** |
| nickname | VARCHAR(50) | 昵称（可空，可重复；注册缺省自动生成） |
| avatar | VARCHAR(255) | 头像 URL（可空） |
| motto | VARCHAR(100) | 个性签名 / 座右铭 |
| total_km | INT | 累计里程（km） |
| total_days | INT | 累计旅行天数 |
| role | VARCHAR(20) | 角色，默认 `USER`；`ADMIN` 为管理员 |
| status | TINYINT | 状态：0 正常 / 1 禁用，默认 0 |
| created_at | DATETIME | 注册时间 |

> **统计字段不入库**：接口返回的 `visitedCities`（已点亮城市数）、`visitedProvinces`（累计省份数）由后端根据 `visited_city` 表实时统计。
>
> **角色与登录态**：登录 / 注册 / `me` 等认证响应的 `user` 对象带 `role`（`USER` / `ADMIN`），前端据此决定是否展示「管理后台」入口。`status` 仅用于账号禁用校验（被禁用的账号不允许登录），不出现在响应中。

### 2.2 visited_city（点亮城市 / 旅行回忆）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 记录 ID |
| user_id | BIGINT FK | 所属用户 |
| city_name | VARCHAR(50) | 城市名 |
| province | VARCHAR(50) | 所在省份 |
| adcode | VARCHAR(20) | 行政区划代码 |
| lat / lng | DOUBLE | 纬度 / 经度（地图点位） |
| color | VARCHAR(10) | 主题色，地图上的城市标记与整市涂色用。前端提供 12 色预设色板，缺省按城市名自动分配 |
| light_date | DATE | 点亮日期（可空） |
| records | JSON | 游玩回忆数组，结构见下 |
| created_at | DATETIME | 创建时间 |

`records` 元素结构（每次游玩一条）：

```json
{ "date": "2026-08-01", "rating": 5, "photos": ["/uploads/a.jpg", "/uploads/b.jpg"] }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| date | String | 游玩日期 `YYYY-MM-DD`。**后端保证非空**：前端未填时写入该城市的点亮日期（点亮日期也为空则当天） |
| rating | Number | 推荐指数 1~5，0 表示未打分 |
| photos | String[] | 照片列表，元素为图片 URL 或 base64 |

### 2.3 plan（旅游规划）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 规划 ID |
| user_id | BIGINT FK | 所属用户 |
| name | VARCHAR(100) | 规划名称 |
| destination | VARCHAR(100) | 目的地 |
| location | VARCHAR(100) | 所在省 / 国家（可空） |
| image | VARCHAR(255) | 封面图（可空，本期前端未上传） |
| start_date | DATE | 出发日期（可空） |
| days | JSON | 每日行程数组 |
| waypoints | JSON | 途径点数组 |
| is_public | TINYINT(1) | 是否公开，**默认 1（公开）** |
| created_at | DATETIME | 创建时间 |

`days` / `waypoints` 结构：

```json
{
  "days": [
    { "title": "第一天", "items": [ { "time": "09:00", "place": "莫高窟", "note": "提前预约门票" } ] }
  ],
  "waypoints": [ { "name": "兰州", "note": "高铁中转" } ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| days[].title | String | 第几天标题（如「第一天」） |
| days[].items[].time | String | 时间，可空（`HH:mm`） |
| days[].items[].place | String | 地点 |
| days[].items[].note | String | 备注（可空） |
| waypoints[].name | String | 途径点名称 |
| waypoints[].note | String | 备注（可空） |

### 2.4 note（社区笔记）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 笔记 ID |
| author_id | BIGINT FK | 作者用户 ID |
| author_nickname | VARCHAR(50) | 作者昵称（冗余，用于列表直接展示） |

| content | TEXT | 正文 |
| image | TEXT | 封面图，可存图片 URL 或 base64 字符串（可空） |
| photos | JSON | 多图数组，元素为 URL 或 base64 |
| location_name | VARCHAR(50) | 关联地点名（可空） |
| location_province | VARCHAR(50) | 地点所在省 / 国家（可空） |
| likes | INT | 点赞数（冗余计数） |
| created_at | DATETIME | 发布时间 |

> 笔记接口中，作者昵称以 `author` 字段返回；地点以嵌套对象 `location: { name, province }` 返回（关联发布时的请求结构）。详情见 [4.5.1](#451-笔记列表)。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 主键 |
| note_id | BIGINT FK | 笔记 ID |

> 唯一约束 `(note_id, user_id)`，防止重复点赞。点赞 / 取消由后端在 [4.5.4](#454-点赞--取消点赞) 中原子维护，并同步更新 `note.likes` 冗余计数。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 主键 |
| content | TEXT | 反馈内容 |
| contact | VARCHAR(100) | 联系方式（可空） |
| images | JSON | 反馈截图 URL 数组（可空，OSS） |

### 2.7 热门目的地（动态统计，不建表）

社区侧栏「热门目的地 Top5」**不再维护静态榜单**，由 `visited_city` 表实时统计：按城市名分组、统计点亮用户数、降序取前 5。接口见 [4.6](#46-热门目的地-hotdestination) 与仪表盘 [5.1](#51-数据统计仪表盘)。

### 2.8 note_comment（笔记评论 / 回复）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 评论 ID |
| note_id | BIGINT FK | 所属笔记 ID（`ON DELETE CASCADE`） |
| user_id | BIGINT FK | 评论者用户 ID（`ON DELETE CASCADE`） |
| parent_id | BIGINT FK NULL | 父评论 ID，自引用 `note_comment(id)`（`ON DELETE CASCADE`）。**NULL = 顶层评论，非空 = 一级回复** |
| content | VARCHAR(500) | 评论内容 |
| likes | INT | 点赞数（冗余计数，与 `comment_like` 行数对应） |
| created_at | DATETIME | 评论时间 |

> 表设计说明：
> 1. **只支持一级回复**：`parent_id` 非空时一定指向一条顶层评论，不存在「回复的回复」。回复也是 `note_comment` 的一行。
> 2. 评论列表按 **`created_at` 倒序**排列，时间相同时按 `likes` 倒序（最新优先——用户发完评论刷新就能在第一条看到自己的）；分页只作用于**顶层评论**，每条顶层评论的回复随它一起返回（回复不分页，按 `created_at` 正序）。
> 3. **删除权限：管理员 / 笔记作者 / 评论作者本人**，三者任一即可删（见 [4.5.7](#457-删除评论)）。
> 4. 删除顶层评论时，其下所有回复由外键 `fk_comment_parent ON DELETE CASCADE` 一并删除。

### 2.9 comment_like（评论点赞记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 主键 |
| comment_id | BIGINT FK | 被点赞的评论 ID（`ON DELETE CASCADE`），**评论与回复共用本表** |
| user_id | BIGINT FK | 点赞用户 ID（`ON DELETE CASCADE`） |
| created_at | DATETIME | 点赞时间 |

> 唯一约束 `(comment_id, user_id)`，防止重复点赞。点赞 / 取消由后端在 [4.5.8](#458-评论点赞--取消点赞) 中原子维护，并同步更新 `note_comment.likes` 冗余计数。

## 四、接口详情

### 4.1 认证 Auth

#### 4.1.1 注册账号

- **方法 & 路径**：`POST /api/auth/register`
- **认证**：无需
- **功能**：创建新账号，成功后**直接返回登录态**（token + 用户信息），前端无需再走登录。
- **提示**：提交前需先 `GET /api/captcha` 获取图形验证码并带回 `uuid`、`code`（见 4.1.5）。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | String | ✅ | 登录用户名，全局唯一 |
| password | String | ✅ | 密码，至少 6 位，BCrypt 加密存储 |
| nickname | String | ❌ | 昵称，**可重复**；缺省时后端自动生成 `user_xxxxxxx` |
| uuid | String | ✅ | 图形验证码编号（`GET /api/captcha` 返回） |
| code | String | ✅ | 用户在图片中看到的字符，忽略大小写 |

**请求示例：**

```json
{ "uuid": "8f7a4b2c...", "code": "A3k9", "username": "zhangsan", "password": "123456", "nickname": "张三" }
```

**成功响应 `data`：** 见下方「登录响应」——即 `{ token, user }`。

**失败场景：** 400（用户名已存在 / 参数不合法 / 验证码错误或已过期）、400（密码过短）。

---

#### 4.1.2 登录

- **方法 & 路径**：`POST /api/auth/login`
- **认证**：无需
- **功能**：校验图形验证码与用户名密码，通过后返回 token 与用户信息。
- **提示**：提交前需先 `GET /api/captcha` 获取图形验证码并带回 `uuid`、`code`（见 4.1.5）。

**请求体：**

```json
{ "uuid": "8f7a4b2c...", "code": "A3k9", "username": "zhangsan", "password": "123456" }
```

**成功响应 `data`：**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user": {
    "id": 1,
    "username": "zhangsan",
    "nickname": "张三",
    "avatar": "https://hcy120.oss-cn-hangzhou.aliyuncs.com/20200414210134_qbeyi.jpg",
    "motto": "",
    "visitedCities": 0,
    "visitedProvinces": 0,
    "totalKm": 0,
    "totalDays": 0
  }
}
```

**失败场景：** 400（用户名或密码错误）、400（验证码错误或已过期）。

> **`avatar` 说明**：用户对象在所有接口中的 `avatar` 字段，若用户未设置头像，后端统一返回默认头像 `https://hcy120.oss-cn-hangzhou.aliyuncs.com/20200414210134_qbeyi.jpg`。前端直接用 `<img :src="user.avatar">` 渲染即可，**无需判空兜底**。

---

#### 4.1.3 退出登录

- **方法 & 路径**：`POST /api/auth/logout`
- **认证**：🔒 需要
- **功能**：服务端清除登录态（无状态 JWT 可仅返回成功）。
- **响应 `data`**：`null`（前端拿到后丢弃本地 token 即可）。

---

#### 4.1.4 获取当前用户

- **方法 & 路径**：`GET /api/auth/me`
- **认证**：🔒 需要

#### 4.3.5 旅行回忆列表（**全量展平，按游玩时间倒序，支持关键词搜索**）

- **方法 & 路径**：`GET /api/visited-cities/memories`
- **认证**：🔒 需要
- **功能**：**仅供「旅行回忆」页使用**。把当前用户每个点亮城市的 `records` 数组**逐条展平**——一条游玩记录 = 一条 `MemoryVO`，同一城市的多条记录各占一条（**不再按城市聚合**）。前端据此渲染「时间隧道」，故**一次性返回全量、不做分页**。支持按地点关键词（城市名 / 省份）在后端做模糊查询。
- **Query 参数**：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| keyword | String | ❌ | 无 | 地点关键词，对 `city_name`、`province` 做 SQL `LIKE %keyword%` 模糊匹配（两字段为 **OR** 关系）。不传 / 传空串则返回全量。自动去除首尾空白 |

> 关键词过滤发生在**城市（行）级**：同一城市的多条游玩记录要么全部命中、要么全部不命中（因为 `city_name` / `province` 是城市级字段）。年份筛选不在后端，由前端在返回结果上过滤。

**响应 `data`（数组）：**

```json
[
  {
    "cityId": 3,
    "recordIndex": 1,
    "cityName": "大理",
    "province": "云南省",
    "adcode": "532900",
    "lat": 25.6,
    "lng": 100.27,
    "color": "#10b981",
    "lightDate": "2026-08-10",
    "date": "2026-08-05",
    "rating": 5,
    "photos": ["https://.../a.jpg", "https://.../b.jpg"]
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| cityId | Number | 所属点亮城市 ID（删除单条记录时回写用） |
| recordIndex | Number | 该记录在 `records` 数组中的下标，配合 `cityId` 唯一定位一条回忆 |
| cityName / province / adcode / lat / lng / color | — | 同所属城市（4.3.1） |
| lightDate | String | 该城市的点亮日期 |
| date | String | **游玩时间** `YYYY-MM-DD`，**保证非空**（见下方兜底规则） |
| rating | Number | 推荐指数 1~5，0 表示未打分 |
| photos | String[] | 该次游玩的照片列表 |

**排序**：按 `date` 倒序；`date` 相同再按 `cityId`、`recordIndex` 升序，保证稳定。

**`date` 兜底规则**：记录里的 `date` 为空 / 空白 → 取该城市的 `lightDate` → `lightDate` 也为空 → 取当天。因此响应中的 `date` 恒非空。
**跳过规则**：`records` 为 `null` / 空数组的城市不产出任何条目。

#### 4.5.5 获取笔记评论列表

- **方法 & 路径**：`GET /api/notes/{id}/comments`
- **认证**：无需（**可选带 token**）
- **功能**：获取指定笔记的评论列表，支持分页。**顶层评论按时间倒序，时间相同时按点赞数倒序**（最新优先）。

**路径参数：**
- `id`：笔记 ID

**查询参数（可选）：**

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | Number | 1 | 页码，从 1 开始 |

> **只支持一级回复**：`replies` 只出现在顶层评论上，回复里恒为空数组。分页作用于顶层评论，回复随父评论一次性返回、不分页（按时间正序）。

```json

      "noteId": 1,
      "parentId": null,

      "likes": 12,
      "liked": true,
      "canDelete": false,
      "createdAt": "2026-08-20 11:30:00",
      "replies": [
        {
          "id": 7,
          "noteId": 1,
          "parentId": 1,
          "authorId": 2,
          "author": "旅行者小A",
          "authorAvatar": null,
          "content": "周二闭馆哦，换周三吧。",
          "likes": 4,
          "liked": false,
          "canDelete": true,
          "createdAt": "2026-08-20 15:00:00",

        }
      ]

  ],
```

> `total` 是**顶层评论**的总数，不含回复。

| canDelete | Boolean | 当前登录用户能否删这条评论（管理员 / 笔记作者 / 评论作者，见 4.5.7）；未登录恒为 `false` |
| createdAt | String | 评论时间 `yyyy-MM-dd HH:mm:ss` |
| replies | Array | 该评论下的一级回复；**只对顶层评论填充**，回复本身为空数组 |

### 4.6 热门目的地 HotDestination（动态统计）

## 五、管理端 Admin

> **权限约定**：管理端接口均在 `/api/admin/**` 下，除登录认证（`Authorization: Bearer <token>`）外，额外要求当前用户 `role=ADMIN`，否则返回 **403**。
>
> 管理员账号由数据库预置（`user.role = 'ADMIN'`），本期不在用户端提供注册入口；管理员登录后认证响应 `user.role = 'ADMIN'`，前端据此展示「管理后台」入口。
>
> 被禁用账号（`status = 1`）无法登录；已登录账号被封禁后，访问管理端接口同样被拒绝（管理端拦截器同时校验 `role` 与 `status`）。

- **失败场景：** 404（笔记不存在）。

> **评论治理不单独设管理端接口**：管理员在社区页 / 笔记详情内即可直接删除任意评论——用户端 [4.5.7](#457-删除评论) 返回的 `canDelete` 对管理员恒为 `true`，权限判断统一在后端完成，管理端无需重复一套评论列表与删除接口。

### 5.4 反馈管理

#### 5.4.1 反馈列表

- **方法 & 路径**：`GET /api/admin/feedbacks`
- **认证**：🔒 ADMIN
- **功能**：分页查看用户反馈，可按处理状态筛选（首页展示待处理数量见 5.1.1）。

**查询参数（均可选）：**

| 参数 | 类型 | 说明 |
|---|---|---|
| handled | Number | 0 待处理 / 1 已处理，不传则全部 |
| page | Number | 页码，从 1 开始，默认 1 |
| pageSize | Number | 每页条数，默认 10 |

**响应 `data`（分页结构）：**

```json
{
  "list": [
    {
      "id": 1,
      "content": "【功能建议】希望增加夜间模式",
      "contact": "me@example.com",
      "images": ["https://oss.example.com/feedback/xxx.png"],
      "handled": false,
      "createdAt": "2026-09-01 12:00:00"
    }
  ],
  "total": 5,
  "page": 1,
  "pageSize": 10
}
```

**`list[]` 元素字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Number | 反馈 ID |
| content | String | 反馈内容 |
| contact | String | 联系方式（可空） |
| images | String[] | 反馈截图 URL 数组（可空） |
| handled | Boolean | false 待处理 / true 已处理 |
| createdAt | String | 提交时间 |

> 列表按 `createdAt` 倒序返回，最新提交的反馈排在最前。

---

#### 5.4.2 标记处理状态

- **方法 & 路径**：`PUT /api/admin/feedbacks/{id}/handled`
- **认证**：🔒 ADMIN
- **功能**：处理反馈后标记为「已处理」，或改回「待处理」。
- **路径参数**：`id` 反馈 ID。

**请求体：**

```json
{ "handled": true }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| handled | Boolean | ✅ | true 已处理 / false 待处理 |

**响应 `data`**：`null`。

**失败场景：** 404（反馈不存在）。

#### 5.4.3 删除反馈

- **方法 & 路径**：`DELETE /api/admin/feedbacks/{id}`
- **认证**：🔒 ADMIN
- **功能**：删除一条反馈记录。
- **路径参数**：`id` 反馈 ID。
- **响应 `data`**：`null`。
- **失败场景：** 404（反馈不存在）。

## 六、前端接入约定

1. **请求封装**：前端 `src/api/http.js` 统一处理 `baseURL=/api`、JSON 序列化、自动附加 `Authorization` 头、统一解包 `{code,message,data}`。非 2xx 或 `code !== 0` 时抛出 `message`，页面直接提示。
2. **Token 存储**：登录 / 注册成功后，将 `token` 存入 `localStorage`，键名 **`footprint-planet:token`**。
3. **Vite 代理**：`vite.config.js` 中已配置 `server.proxy['/api'] -> http://localhost:8080`，开发时前端直接写 `/api/...` 即可，无需处理跨域。
4. **登录态恢复**：应用启动时若存在 token，调用 `GET /api/auth/me` 恢复用户信息；收到 **401** 则清空 token 并回到登录页。
5. **图片上传**：发布笔记 / 点亮城市 / 提交反馈的图片一律先调 `POST /api/upload`（见 [4.8](#48-图片上传-upload)，**无需登录**）上传到阿里云 OSS，用返回的 URL 填充 `image`、`photos[]`、`records[].photos[]`、`images[]` 等字段（上传期间按钮进入「上传中…」禁用态）。头像本期不提供上传。
6. **管理端入口**：认证响应 / `me` 中 `user.role = 'ADMIN'` 时前端展示「管理后台」入口；管理端所有请求带同一 token，收到 **403**（非管理员）或 **401**（登录过期 / 被禁用）时按通用逻辑处理。
7. **作者主页联动**：社区点击作者（笔记 `list[].authorId`）→ 依次调用 `GET /api/users/{userId}`、`GET /api/notes?authorId={userId}&page=&pageSize=`、`GET /api/users/{userId}/plans?page=&pageSize=`（笔记与规划均**真分页**）。「使用这份规划」走 `POST /api/plans/{id}/copy`，由后端复制为当前用户的公开规划（前端不组装字段、不做重复校验，重复复制会生成多份副本）；需要单独取规划详情时用 `GET /api/plans/{id}`（公开规划可读）。**authorId 缺失的旧数据视为不可点击**，前端给出提示而非继续查询。
