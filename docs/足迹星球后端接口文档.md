## 一、运行约定

| 项 | 约定 |
|---|---|
| Base URL | `http://localhost:8080/api` |
| 认证方式 | JWT，请求头携带 `Authorization: Bearer <token>` |
| 内容类型 | `application/json`（UTF-8） |
| 响应包装 | 统一 JSON 结构 `{ code, message, data }` |
| 成功标志 | `code = 0` |
| 翻页响应 | `{ list: [...], total: 100, page: 1, pageSize: 10 }` |
| 游标响应 | `{ list: [...], nextCursor, hasMore }` |
| 时间格式 | 日期 `YYYY-MM-DD`；时间戳 `yyyy-MM-ddTHH:mm:ss`（ISO-8601，含 `T`，前端展示时自行替换） |

### 1.1 统一响应包装

所有接口（成功）返回：

```json
{ "code": 0, "message": "ok", "data": { } }
```

`data` 的具体内容见各接口。失败时返回 **HTTP 200**，`code` 用业务码表达错误类别：

```json
{ "code": 400, "message": "用户名或密码错误", "data": null }
```

> 前端 `src/api/http.js` 会统一解包：`code !== 0` 均抛出 `message` 作为错误提示，因此各接口直接返回业务提示文案即可。

### 1.2 错误码

| code | 含义 |
|---|---|
| 400 | 参数 / 业务错误（含验证码错误、密码错误、权限不足的语义性提示） |
| 401 | 未认证（token 缺失 / 失效） |
| 403 | 无权限（非管理员访问管理端、editor 越权做 owner 操作） |
| 404 | 资源不存在 |
| 409 | 乐观锁冲突（计划已被他人修改，请刷新后重试） |
| 500 | 服务器异常 |

### 1.3 认证方式

- 标注「🔒」的接口必须在请求头携带 `Authorization: Bearer <token>`。
- token 由登录 / 注册接口签发，前端存于 `localStorage`，键名 `footprint-planet:token`。
- 后端从 JWT 解析出当前用户身份，用于「我的数据」查询、作者校验、点赞用户标识等。
- token 失效 / 非法时返回 **401**，前端收到后清除 token 并跳转登录页。

### 1.4 命名映射约定

数据库使用下划线命名，接口（请求 / 响应）统一使用 **camelCase**，对应关系如下：

| 数据库字段 | 接口字段 | 说明 |
|---|---|---|
| `created_at` | `createdAt` | 时间戳 |
| `total_km` | `totalKm` | 累计里程 |
| `total_days` | `totalDays` | 累计天数 |
| `light_date` | `lightDate` | 点亮日期 |
| `start_date` | `startDate` | 出发日期 |
| `is_public` | `isPublic` | 是否公开 |
| `author_id` | `authorId` | note 响应中的作者 ID |
| `author_nickname` | `author` | note 响应中的作者昵称（仅展示） |
| `location_name` / `location_province` | `location.name` / `location.province` | note 地点（嵌套对象） |
| `user_id` | `userId` | plan 的 owner 用户 ID |
| `day_no` / `sort_no` | `dayNo` / `sortNo` | plan_item 的第几天 / 当天顺序 |
| `poi_id` | `poiId` | 高德 POI ID |
| `from_item_id` / `to_item_id` | `fromItemId` / `toItemId` | plan_leg 起终点 |
| `collab_locked` / `collab_deadline` | `collabLocked` / `collabDeadline` | 协作锁定 / 截止时间 |
| `max_uses` / `used_count` | `maxUses` / `usedCount` | 邀请次数上限 / 已用次数 |
| `sender_nickname` / `sender_avatar` | `senderNickname` / `senderAvatar` | 通知触发者 |

其余字段名两端一致（如 `username`、`nickname`、`motto`、`avatar`）。

### 1.5 两套分页

- **翻页式**（`PageVO { list, total, page, pageSize }`）：规划列表、笔记列表、作者公开规划、管理端列表。由 MyBatis-Plus 分页插件输出。
- **游标式**（`{ list, nextCursor, hasMore }`）：评论列表、通知列表。统一用 `lt(id, cursor)` + `orderByDesc(id)`，`cursor` 为上一批最后一条的 id（首页省略 / 传 null），多查一条判定 `hasMore`。前端滚动加载只消费 `nextCursor` / `hasMore`，不做分页计算。

## 二、数据模型

> 说明：以下为物理表设计。接口返回的 JSON 字段名遵循上一节映射规则，**与表字段不完全同名**。共 **13 张表**。

### 2.1 user（用户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 用户 ID |
| username | VARCHAR(50) UNIQUE | 登录名 |
| password | VARCHAR(100) | BCrypt 加密后的密码，**不出现在任何响应中** |
| nickname | VARCHAR(50) | 昵称（可空，可重复；注册缺省自动生成） |
| avatar | VARCHAR(255) | 头像 URL（可空） |
| motto | VARCHAR(100) | 个性签名 / 座右铭 |
| total_km | INT | 累计里程（km） |
| total_days | INT | 累计旅行天数 |
| role | VARCHAR(20) | 角色，默认 `USER`；`ADMIN` 为管理员 |
| status | TINYINT | 状态：0 正常 / 1 禁用，默认 0 |
| created_at | DATETIME | 注册时间 |

> **统计字段不入库**：接口返回的 `visitedCities`（已点亮城市数）、`visitedProvinces`（累计省份数）由后端根据 `visited_city` 表实时统计。
> **角色与登录态**：登录 / 注册 / `me` 等认证响应的 `user` 对象带 `role`（`USER` / `ADMIN`），前端据此决定是否展示「管理后台」入口。`status` 仅用于账号禁用校验（被禁用的账号不允许登录），不出现在响应中。

### 2.2 visited_city（点亮城市 / 旅行回忆）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 记录 ID |
| user_id | BIGINT FK | 所属用户 |
| city_name | VARCHAR(50) | 城市名 |
| province | VARCHAR(50) | 所在省份 |
| adcode | VARCHAR(20) | 行政区划代码 |
| lat / lng | DOUBLE | 纬度 / 经度（地图点位） |
| color | VARCHAR(10) | 主题色，地图上的城市标记与整市涂色用。前端提供 12 色预设色板，缺省按城市名自动分配 |
| light_date | DATE | 点亮日期（可空） |
| records | JSON | 游玩回忆数组，结构见下 |
| created_at | DATETIME | 创建时间 |

`records` 元素结构（每次游玩一条）：

```json
{ "date": "2026-08-01", "rating": 5, "photos": ["/uploads/a.jpg", "/uploads/b.jpg"] }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| date | String | 游玩日期 `YYYY-MM-DD`。**后端保证非空**：前端未填时写入该城市的点亮日期（点亮日期也为空则当天） |
| rating | Number | 推荐指数 1~5，0 表示未打分 |
| photos | String[] | 照片列表，元素为图片 URL 或 base64 |

### 2.3 plan（旅游规划）

> v2.0 起「行程」不再用 `days/waypoints` JSON 大字段，改为独立表 `plan_item` / `plan_leg`（见 2.4 / 2.5）；协作与邀请用 `plan_collaborator` / `plan_invite`（见 2.6 / 2.7）。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 规划 ID |
| user_id | BIGINT FK | 所属用户（owner） |
| name | VARCHAR(100) | 规划名称 |
| destination | VARCHAR(100) | 目的地 |
| location | VARCHAR(100) | 所在省 / 国家（可空） |
| image | VARCHAR(255) | 封面图（可空） |
| start_date | DATE | 出发日期（可空） |
| is_public | TINYINT(1) | 是否公开，**默认 1（公开）** |
| version | INT | 乐观锁版本号（写操作 +1，`@Version`） |
| collab_locked | TINYINT(1) | 协作锁定（1 锁定 / 0 未锁定） |
| collab_deadline | DATETIME | 创作截止时间（可空 = 不限时） |
| created_at | DATETIME | 创建时间 |

### 2.4 plan_item（行程地点条目）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 条目 ID |
| plan_id | BIGINT FK | 所属计划（`ON DELETE CASCADE`） |
| day_no | INT | 第几天（从 1 开始） |
| sort_no | INT | 当天顺序（数组下标语义） |
| name | VARCHAR(100) | 地点名称（高德 POI 正规名称） |
| lng / lat | DECIMAL(10,6) | 经纬度（GCJ-02） |
| poi_id | VARCHAR(64) | 高德 POI ID（预留：地点唯一标识 / 校验） |
| note | VARCHAR(500) | 用户备注 |
| created_at | DATETIME | 创建时间 |

### 2.5 plan_leg（相邻条目交通段）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 交通段 ID |
| plan_id | BIGINT FK | 所属计划（`ON DELETE CASCADE`） |
| from_item_id | BIGINT FK | 起点条目（`ON DELETE CASCADE`） |
| to_item_id | BIGINT FK | 终点条目（`ON DELETE CASCADE`） |
| mode | VARCHAR(20) | 交通方式：driving / walking / transit |
| duration | INT | 时长（秒） |
| distance | INT | 距离（米） |
| summary | VARCHAR(255) | 方案摘要（如「地铁2号线→10号线，52分钟」） |
| polyline | TEXT | 真实路线坐标串（画线用，`"lng,lat;lng,lat;..."`） |
| created_at | DATETIME | 创建时间 |

> 同一 `from_item_id` 只保留一条（`saveLeg` 覆盖式：先删同起点旧 leg 再插入），避免「修改方案」堆积重复记录。

### 2.6 plan_collaborator（计划协作者）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 关系 ID |
| plan_id | BIGINT FK | 计划（`ON DELETE CASCADE`） |
| user_id | BIGINT FK | 用户（`ON DELETE CASCADE`） |
| role | VARCHAR(20) | 角色：editor / viewer（owner 由 `plan.user_id` 判定） |
| joined_at | DATETIME | 加入时间 |

> 唯一约束 `(plan_id, user_id)`。**三级角色**：`owner`（`plan.user_id`）/ `editor` / `viewer`。

### 2.7 plan_invite（计划邀请链接）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 邀请 ID |
| token | VARCHAR(64) UNIQUE | 随机串（UUID），链接主体 |
| plan_id | BIGINT FK | 目标计划（`ON DELETE CASCADE`） |
| role | VARCHAR(20) | 进入后的角色：editor / viewer |
| expires_at | DATETIME | 过期时间（可空 = 不过期） |
| max_uses | INT | 次数上限（0 = 不限） |
| used_count | INT | 已用次数 |
| created_by | BIGINT | 邀请人 |
| revoked | TINYINT(1) | 是否已撤销 |
| created_at | DATETIME | 创建时间 |

### 2.8 note（社区笔记）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 笔记 ID |
| author_id | BIGINT FK | 作者用户 ID |
| author_nickname | VARCHAR(50) | 作者昵称（冗余，用于列表直接展示） |
| title | VARCHAR(100) | 标题 |
| content | TEXT | 正文 |
| image | TEXT | 封面图，可存图片 URL 或 base64 字符串（可空） |
| photos | JSON | 多图数组，元素为 URL 或 base64 |
| location_name | VARCHAR(50) | 关联地点名（可空） |
| location_province | VARCHAR(50) | 地点所在省 / 国家（可空） |
| likes | INT | 点赞数（冗余计数） |
| created_at | DATETIME | 发布时间 |

> 笔记接口中，作者昵称以 `author` 字段返回；地点以嵌套对象 `location: { name, province }` 返回。详情见 [4.7.1](#471-笔记列表)。

### 2.9 note_like（点赞记录）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 主键 |
| note_id | BIGINT FK | 笔记 ID |
| user_id | BIGINT FK | 点赞用户 ID |
| created_at | DATETIME | 点赞时间 |

> 唯一约束 `(note_id, user_id)`，防止重复点赞。

### 2.10 note_comment（笔记评论 / 回复）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 评论 ID |
| note_id | BIGINT FK | 所属笔记 ID（`ON DELETE CASCADE`） |
| user_id | BIGINT FK | 评论者用户 ID（`ON DELETE CASCADE`） |
| parent_id | BIGINT FK NULL | 父评论 ID，自引用 `note_comment(id)`（`ON DELETE CASCADE`）。**NULL = 顶层评论，非空 = 一级回复** |
| content | VARCHAR(500) | 评论内容 |
| likes | INT | 点赞数（冗余计数，与 `comment_like` 行数对应） |
| created_at | DATETIME | 评论时间 |

> 表设计说明：
> 1. **只支持一级回复**：`parent_id` 非空时一定指向一条顶层评论，不存在「回复的回复」。回复也是 `note_comment` 的一行。
> 2. 评论列表按 **`id` 倒序**（游标分页），分页只作用于**顶层评论**，每条顶层评论的回复随它一起返回（回复不分页，按 `created_at` 正序）。
> 3. **删除权限：管理员 / 笔记作者 / 评论作者本人**，三者任一即可删（见 [4.8.3](#483-删除评论)）。
> 4. 删除顶层评论时，其下所有回复由外键 `fk_comment_parent ON DELETE CASCADE` 一并删除。

### 2.11 comment_like（评论点赞记录）

| 字段 | 类型 | 说明 |
|---|---|---|

| user_id | BIGINT FK | 点赞用户 ID（`ON DELETE CASCADE`） |
| created_at | DATETIME | 点赞时间 |

> 唯一约束 `(comment_id, user_id)`，防止重复点赞。

|---|---|---|

| type | VARCHAR(20) | 类型：like_note / comment / reply / like_comment |
| sender_id | BIGINT | 触发者用户 id |

> 通知在触发点赞 / 评论 / 回复时**落库 + WebSocket 实时推送**；列表查询按 `type` 分「点赞 / 评论」两类，游标分页（见 [4.9](#49-消息通知-notification)）。

### 2.14 热门目的地（动态统计，不建表）

社区侧栏「热门目的地 Top5」**不再维护静态榜单**，由 `visited_city` 表实时统计：按城市名分组、统计点亮用户数、降序取前 5。接口见 [4.10](#410-热门目的地-hotdestination) 与仪表盘 [5.1](#51-数据统计仪表盘)。

## 四、接口详情

### 4.1 认证 Auth

#### 4.1.1 注册账号

- **方法 & 路径**：`POST /api/auth/register`
- **认证**：无需
- **功能**：创建新账号，成功后**直接返回登录态**（token + 用户信息），前端无需再走登录。
- **提示**：提交前需先 `GET /api/captcha` 获取图形验证码并带回 `uuid`、`code`（见 4.1.5）。

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| username | String | ✅ | 登录用户名，全局唯一 |
| password | String | ✅ | 密码，至少 6 位，BCrypt 加密存储 |
| nickname | String | ❌ | 昵称，**可重复**；缺省时后端自动生成 `user_xxxxxxx` |
| uuid | String | ✅ | 图形验证码编号（`GET /api/captcha` 返回） |
| code | String | ✅ | 用户在图片中看到的字符，忽略大小写 |

**请求示例：**

```json
{ "uuid": "8f7a4b2c...", "code": "A3k9", "username": "zhangsan", "password": "123456", "nickname": "张三" }
```

**成功响应 `data`：** 见下方「登录响应」——即 `{ token, user }`。

**失败场景：** 400（用户名已存在 / 参数不合法 / 验证码错误或已过期）、400（密码过短）。

---

#### 4.1.2 登录

- **方法 & 路径**：`POST /api/auth/login`
- **认证**：无需
- **功能**：校验图形验证码与用户名密码，通过后返回 token 与用户信息。
- **提示**：提交前需先 `GET /api/captcha` 获取图形验证码并带回 `uuid`、`code`（见 4.1.5）。

**请求体：**

```json
{ "uuid": "8f7a4b2c...", "code": "A3k9", "username": "zhangsan", "password": "123456" }
```

**成功响应 `data`：**

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user": {
    "id": 1,
    "username": "zhangsan",
    "nickname": "张三",
    "avatar": "https://hcy120.oss-cn-hangzhou.aliyuncs.com/20200414210134_qbeyi.jpg",
    "motto": "",
    "visitedCities": 0,
    "visitedProvinces": 0,
    "totalKm": 0,
    "totalDays": 0
  }
}
```

**失败场景：** 400（用户名或密码错误）、400（验证码错误或已过期）。

> **`avatar` 说明**：用户对象在所有接口中的 `avatar` 字段，若用户未设置头像，后端统一返回默认头像 `https://hcy120.oss-cn-hangzhou.aliyuncs.com/20200414210134_qbeyi.jpg`。前端直接用 `<img :src="user.avatar">` 渲染即可，**无需判空兜底**。

#### 4.1.3 退出登录

- **方法 & 路径**：`POST /api/auth/logout`
- **认证**：🔒 需要
- **功能**：服务端清除登录态（无状态 JWT 可仅返回成功）。
- **响应 `data`**：`null`（前端拿到后丢弃本地 token 即可）。

---

#### 4.1.4 获取当前用户

- **方法 & 路径**：`GET /api/auth/me`
- **认证**：🔒 需要
- **功能**：应用启动时用 token 恢复登录状态，返回当前用户信息（含统计字段）。
- **响应 `data`**：`user` 对象，结构与 4.1.2 相同。
- **失败场景**：401（token 失效或缺失）——前端据此清除 token 并回到登录页。

---

#### 4.1.5 获取图形验证码（注册 / 登录前置）

- **方法 & 路径**：`GET /api/captcha`
- **认证**：无需
- **功能**：生成 4 位字母数字图形验证码并下发。注册（4.1.1）、登录（4.1.2）前必须先调用本接口，提交时带上返回的 `uuid` 与用户在图片中看到的 `code`。
- **存储与有效期**：`code` 存 Redis（key `captcha:{uuid}`），**2 分钟**有效，**一次性**（校验成功即作废，防止重放）。前端**点击图片即可刷新**（重新请求本接口拿到新 `uuid` 与图）。
- **成功响应 `data`：**

```json
{
  "uuid": "8f7a4b2c9e1d4f3a",
  "img": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUg..."
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| uuid | String | 验证码编号，登录 / 注册请求体原样带回 |
| img | String | PNG 图片 base64（data URL），前端直接用作 `<img src>` |

- **失败场景**：无（仅服务器异常返回 500）。

#### 4.3.5 旅行回忆列表（全量展平，按游玩时间倒序，支持关键词搜索）

- **方法 & 路径**：`GET /api/visited-cities/memories`
- **认证**：🔒 需要
- **功能**：**仅供「旅行回忆」页使用**。把当前用户每个点亮城市的 `records` 数组**逐条展平**——一条游玩记录 = 一条 `MemoryVO`，同一城市的多条记录各占一条（**不再按城市聚合**）。前端据此渲染「时间隧道」，故**一次性返回全量、不做分页**。支持按地点关键词（城市名 / 省份）在后端做模糊查询。
- **Query 参数**：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| keyword | String | ❌ | 无 | 地点关键词，对 `city_name`、`province` 做 SQL `LIKE %keyword%` 模糊匹配（两字段为 **OR** 关系）。不传 / 传空串则返回全量。自动去除首尾空白 |

> 关键词过滤发生在**城市（行）级**：同一城市的多条游玩记录要么全部命中、要么全部不命中（因为 `city_name` / `province` 是城市级字段）。年份筛选不在后端，由前端在返回结果上过滤。

**响应 `data`（数组）：**

```json
[
  {
    "cityId": 3,
    "recordIndex": 1,
    "cityName": "大理",
    "province": "云南省",
    "adcode": "532900",
    "lat": 25.6,
    "lng": 100.27,
    "color": "#10b981",
    "lightDate": "2026-08-10",
    "date": "2026-08-05",
    "rating": 5,
    "photos": ["https://.../a.jpg", "https://.../b.jpg"]
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| cityId | Number | 所属点亮城市 ID（删除单条记录时回写用） |
| recordIndex | Number | 该记录在 `records` 数组中的下标，配合 `cityId` 唯一定位一条回忆 |
| cityName / province / adcode / lat / lng / color | — | 同所属城市（4.3.1） |
| lightDate | String | 该城市的点亮日期 |
| date | String | **游玩时间** `YYYY-MM-DD`，**保证非空**（见下方兜底规则） |
| rating | Number | 推荐指数 1~5，0 表示未打分 |
| photos | String[] | 该次游玩的照片列表 |

**排序**：按 `date` 倒序；`date` 相同再按 `cityId`、`recordIndex` 升序，保证稳定。

**`date` 兜底规则**：记录里的 `date` 为空 / 空白 → 取该城市的 `lightDate` → `lightDate` 也为空 → 取当天。因此响应中的 `date` 恒非空。
**跳过规则**：`records` 为 `null` / 空数组的城市不产出任何条目。

### 4.4 旅游规划 Plan

> **三级角色**：`owner`（`plan.user_id`）/ `editor` / `viewer`。权限校验顺序：**角色 → 协作状态（locked/deadline）→ 写入**。
> - 条目增删改 / 排序 / 交通段 = `requireEditor`（editor 可，viewer 不可）；
> - 删计划 / 封面 / 锁定 / 截止 / 移除成员 / 撤销与更新邀请 = `requireOwner`（仅 owner 可）。
> - **乐观锁**：所有写操作走 `version` CAS，冲突返回 409。
> - **协作锁定**：`collabLocked=true` 或已过 `collabDeadline` 时，**editor 被拒绝写入**（返回 403「计划已锁定或已到截止时间，暂不可编辑」），**owner 不受限**。

#### 4.4.1 我的规划列表（我创建 + 我参与）

- **方法 & 路径**：`GET /api/plans`
- **认证**：🔒 需要
- **功能**：返回当前用户**创建 + 协作参与**的规划（合并去重，**真分页**，按 `created_at` 倒序）。列表元素为**基本信息**（不含 `items`/`legs`），额外带 `collaborated` 标记是否「协作参与」。
- **Query 参数**：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| page | Number | ❌ | 1 | 页码，从 1 开始 |
| pageSize | Number | ❌ | 10 | 每页条数 |

**响应 `data`：** 分页包装，`list` 元素为 Plan 基本信息对象：

```json
{
  "list": [
    {
      "id": 1,
      "userId": 2,
      "name": "杭州三日游",
      "destination": "杭州",
      "location": "浙江省",
      "image": "https://.../cover.jpg",
      "startDate": "2026-10-01",
      "isPublic": true,
      "collabLocked": false,
      "collabDeadline": null,
      "collaborated": false,
      "createdAt": "2026-09-20T10:00:00"
    }
  ],
  "total": 9,
  "page": 1,
  "pageSize": 10
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| collaborated | Boolean | 是否「协作参与」的计划（非 owner）；`true` 时前端显示「👥 协作」标签，并隐藏 owner 专属操作 |

---

#### 4.4.2 规划详情

- **方法 & 路径**：`GET /api/plans/{id}`
- **认证**：公开规划无需登录；私有规划需是**成员**（owner / editor / viewer）之一

```json
  "createdAt": "2026-09-20T10:00:00",

    { "userId": 3, "nickname": "张三", "avatar": "...", "role": "editor", "joinedAt": "..." }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| version | Integer | 当前乐观锁版本号（前端 `reorderItems` 回传用） |

### 4.5 邀请链接 Invite

> 邀请能力：**签发 / 核销 / 撤销 / 更新 / 列表**。签发改 owner、更新 / 撤销 / 列表均 owner。
> **关键语义**：更新邀请的 `role` 只影响「之后通过该链接加入的人」，不会改动已加入成员的角色；因 `token` 不变，**已发出去的链接不会失效**。

#### 4.5.1 签发邀请链接

- **方法 & 路径**：`POST /api/plans/{planId}/invites`
- **认证**：🔒 需要（**仅 owner**）
- **功能**：生成一个邀请链接（token + 完整链接），落地 `plan_invite`。
- **路径参数**：`planId` 计划 ID。

**请求体：**

```json
{ "role": "editor", "maxUses": 5, "expiresAt": "2026-11-10T23:59:00" }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| role | String | ✅ | 进入后的角色：`editor` / `viewer` |
| maxUses | Integer | ❌ | 次数上限，**0 = 不限**（缺省 0） |
| expiresAt | String | ❌ | 过期时间（ISO-8601，可空 = 不过期） |

**响应 `data`：** `PlanInviteVO`（含 `token`、`link` 完整邀请链接、`usedCount` 等）。

---

#### 4.5.2 核销邀请（接受链接）

- **方法 & 路径**：`POST /api/invites/{token}/accept`
- **认证**：🔒 需要（登录用户）
- **功能**：校验邀请链接有效性后加入计划（**幂等**）。
- **路径参数**：`token` 邀请 token。
- **行为**：
  1. token 不存在 → 404；已撤销 / 已过期 / 次数用完 → 400。
  2. 查当前用户在该计划的现有角色：
     - **已是成员（owner/editor/viewer）→ 幂等返回现有角色，什么都不改**（不消耗次数、不重复插入）。
     - 非成员 → 用链接里的 `role` 写入 `plan_collaborator`，`usedCount + 1`，广播 `member_join`。
- **响应 `data`**：`{ "planId": 1, "role": "editor" }`。

> **角色一经确定不再变**：已是成员再点任何链接，都返回现有角色（不升级 / 不降级）。改成员角色目前只有「移除成员 → 重新邀请」一条路。

---

#### 4.5.3 更新邀请链接

- **方法 & 路径**：`PUT /api/plans/{planId}/invites/{inviteId}`
- **认证**：🔒 需要（**仅 owner**）
- **功能**：修改邀请的角色 / 次数上限 / 过期时间。**token 不变，链接不变**（已发出去的链接继续有效，不用重新申请）。
- **路径参数**：`planId` 计划 ID、`inviteId` 邀请 ID。

**请求体：**

```json
{ "role": "viewer", "maxUses": 10, "expiresAt": null }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| role | String | ✅ | `editor` / `viewer` |
| maxUses | Integer | ✅ | 次数上限（0 = 不限）。**不能小于 `usedCount`**，否则 400 |
| expiresAt | String | ❌ | 过期时间（null = 不过期） |

- **失败场景**：404（邀请不存在）、400（已撤销 / `maxUses < usedCount`）。
- **响应 `data`**：更新后的 `PlanInviteVO`。

---

#### 4.5.4 撤销邀请

### 4.7 社区笔记 Note

#### 4.7.1 笔记列表（搜索 / 分页 / 按作者）

- **方法 & 路径**：`GET /api/notes`
- **认证**：无需（可选带 token —— 见下方说明）
- **功能**：社区笔记流，支持关键词搜索、按作者过滤、排序（最新 / 最热）、分页。

> **可选认证**：本接口不强制登录。若请求头带了有效 token，后端会解析出当前用户，用于计算每条笔记的 `liked` 字段；未带 token 或 token 已失效则按匿名处理，`liked` 一律为 `false`，请求正常返回。

**查询参数（均可选）：**

| 参数 | 类型 | 说明 |
|---|---|---|
| keyword | String | 标题 / 内容 / 作者昵称 / 地点（名称、省份）模糊搜索 |
| authorId | Number | 按作者 **userId** 过滤（用于作者主页笔记分页，昵称可重复不用于查询） |
| sort | String | 排序方式：`latest` 最新发布（默认，按 `created_at` 倒序）/ `hot` 按点赞数倒序 |
| page | Number | 页码，从 1 开始，默认 1 |
| pageSize | Number | 每页条数，默认 6 |

> **keyword 命中范围**：`title` / `content` / `author_nickname` / `location_name` / `location_province` 任一列模糊匹配（`LIKE %kw%`），各列之间为「或」。作者昵称与地点在 `note` 表是**冗余列**，因此本接口**无需关联 `user` 表**。

> **排序在服务端完成**：`sort` 作用于**全量结果**排序后再分页（不是页内排序）。前端切换「时间 / 点赞」应带上 `sort` 重新请求，不要对当前页做本地排序。

**响应 `data`（分页结构）：**

```json

  "list": [
    {
      "id": 1,
      "title": "巴黎七日漫游指南",
      "content": "沿着塞纳河漫步……",
      "image": "",
      "photos": [],
      "location": { "name": "巴黎", "province": "法国" },
      "authorId": 2,
      "author": "旅行者小A",
      "authorAvatar": "https://hcy120.oss-cn-hangzhou.aliyuncs.com/20200414210134_qbeyi.jpg",
      "likes": 2400,
      "liked": true,
      "commentCount": 5,
      "createdAt": "2026-08-20T10:00:00"
    }
  ],
  "total": 8,
  "page": 1,
  "pageSize": 6
}
```

**`list[]` 元素字段：**

#### 4.8.2 发布评论 / 回复

- **方法 & 路径**：`POST /api/notes/{noteId}/comments`
- **认证**：🔒 需要

|---|---|---|---|
| content | String | ✅ | 评论内容，不能为空字符串，最大 500 字符 |

#### 4.8.3 删除评论

- **方法 & 路径**：`DELETE /api/notes/{noteId}/comments/{commentId}`
- **认证**：🔒 需要
- **功能**：删除一条评论。
- **删除权限（三者任一即可）**：
  1. **管理员**（`role = ADMIN`）
  2. **笔记作者**（该评论所属笔记的 `author_id`）
  3. **评论作者本人**（该评论的 `user_id`）

- **路径参数**：`noteId` 笔记 ID、`commentId` 评论 ID。

**响应 `data`：** `null`
**失败场景：** 404（笔记或评论不存在）、403（三者都不是）。

#### 4.8.4 评论点赞 / 取消点赞

- **方法 & 路径**：`POST /api/notes/{noteId}/comments/{commentId}/like`
- **认证**：🔒 需要
- **功能**：点赞或取消点赞一条评论。**回复同样适用**（回复也是评论，走同一个接口）。点赞时给评论作者推送通知（`like_comment`）。
- **路径参数**：`noteId` 笔记 ID、`commentId` 评论 ID（可以是回复的 ID）。

**请求体：**

```json

```

**响应 `data`：**


- 幂等：重复点赞不会重复计数（靠 `comment_like` 的唯一键 `(comment_id, user_id)`），重复取消同理。

**失败场景：** 404（笔记或评论不存在）。

## 五、管理端 Admin

> **权限约定**：管理端接口均在 `/api/admin/**` 下，除登录认证（`Authorization: Bearer <token>`）外，额外要求当前用户 `role=ADMIN`，否则返回 **403**。
>
> 管理员账号由数据库预置（`user.role = 'ADMIN'`），本期不在用户端提供注册入口；管理员登录后认证响应 `user.role = 'ADMIN'`，前端据此展示「管理后台」入口。
>
> 被禁用账号（`status = 1`）无法登录；已登录账号被封禁后，访问管理端接口同样被拒绝（管理端拦截器同时校验 `role` 与 `status`）。

#### 5.2.2 用户详情

- **方法 & 路径**：`GET /api/admin/users/{id}`
- **认证**：🔒 ADMIN

- **响应 `data`**：字段在 5.2.1 基础上补充 `avatar`、`totalKm`、`totalDays`、`visitedProvinces`（点亮省份数）。

**失败场景：** 404（用户不存在）。

## 六、前端接入约定

1. **请求封装**：前端 `src/api/http.js` 统一处理 `baseURL=/api`、JSON 序列化、自动附加 `Authorization` 头、统一解包 `{code,message,data}`。`code !== 0` 时抛出 `message`，页面直接提示。
2. **Token 存储**：登录 / 注册成功后，将 `token` 存入 `localStorage`，键名 **`footprint-planet:token`**。
3. **Vite 代理**：`vite.config.js` 中已配置 `server.proxy['/api'] -> http://localhost:8080`，开发时前端直接写 `/api/...` 即可，无需处理跨域。
4. **登录态恢复**：应用启动时若存在 token，调用 `GET /api/auth/me` 恢复用户信息；收到 **401** 则清空 token 并回到登录页。
5. **图片上传**：发布笔记 / 点亮城市 / 提交反馈的图片一律先调 `POST /api/upload`（见 [4.12](#412-图片上传-upload)，**无需登录**）上传到阿里云 OSS，用返回的 URL 填充 `image`、`photos[]`、`records[].photos[]`、`images[]` 等字段（上传期间按钮进入「上传中…」禁用态）。头像本期不提供上传。
6. **管理端入口**：认证响应 / `me` 中 `user.role = 'ADMIN'` 时前端展示「管理后台」入口；管理端所有请求带同一 token，收到 **403**（非管理员）或 **401**（登录过期 / 被禁用）时按通用逻辑处理。
7. **作者主页联动**：社区点击作者（笔记 `list[].authorId`）→ 依次调用 `GET /api/users/{userId}`、`GET /api/notes?authorId={userId}&page=&pageSize=`、`GET /api/users/{userId}/plans?page=&pageSize=`（笔记与规划均**真分页**）。「使用这份规划」走 `POST /api/plans/{id}/copy`，由后端复制为当前用户的公开规划（前端不组装字段、不做重复校验，重复复制会生成多份副本）；需要单独取规划详情时用 `GET /api/plans/{id}`（公开规划可读）。**authorId 缺失的旧数据视为不可点击**，前端给出提示而非继续查询。
8. **协作计划**：我的规划列表返回「我创建 + 我参与」的合并列表，`collaborated=true` 表示协作参与（前端据此显示「👥 协作」标签、隐藏 owner 专属操作）。进入编辑页后按 `myRole`（owner/editor/viewer）控制界面权限：条目增删改/排序/交通段 editor 可；删计划/封面/锁定/截止/移除成员/邀请管理 owner 可。editor 在锁定或过截止时间后，操作按钮仍保留，点击时前端 `ensureEditable()` 统一提示「计划已锁定或已到截止时间，暂不可编辑」。
9. **实时同步**：编辑页通过 STOMP 订阅 `/topic/plan/{planId}` 实时接收他人操作广播（成员加入、条目增删改、排序、出行方案、锁定、截止、移除成员等），自己操作本地刷新、忽略自己的广播；收到他人广播才重新拉详情。消息通知通过 `/user/queue/notifications` 实时推送（点赞 / 评论 / 回复）。
10. **算路与真实路线**：前端「选出行方案」调 `POST /api/route/search`（后端高德 Web 服务）拿方案 + `polyline`，选中后 `saveLeg` 存 `polyline`；地图渲染时读 `leg.polyline` 画真实路线（无 `polyline` 的历史数据回退直线）。
